取り込みから 4 択クイズまでの流れに、混同しやすい語の再出題、発音やキーボード操作、学習状況の表示が備わる。引き継ぎコード・バックアップ・各種書き出し・復元などのデータ保全手段があり、端末内 OCR や通信先の説明も実際の通信と一致していた。レビューではアクセシビリティ等の Lighthouse 評価と、1500 語のリスト操作も確認された。

- 初回読み込みは単一 HTML で約 1.3MB。Service Worker によって 2 回目以降は軽くなるが、初回は弱い回線で負担になる可能性がある。JS 分割や HTTP キャッシュの改善余地がある。
- 確認画面（手順 2）では、1500 語すべてが編集可能な入力欄として描画される。今回の操作では動作したが、古い端末では表示負荷が出る可能性がある（推測）。
- 初期の「今日の復習」は 0 語で、SRS の復習対象が増えるまで立ち上がりに間がある。即日リフレッシュの機会があると把握しやすい、との指摘。
- UI は日本語のみ。日本人学習者向けなら問題ない、との指摘。
- 写真 OCR は Tesseract 依存で、手ぶれや影があると精度が下がる。端末内・無料という設計とのトレードオフを踏まえた指摘。

## 起票する issue の本文案

### 確認画面の候補を段階表示する

**背景**

確認画面（手順 2）は `renderCandidates()` が候補全件を描画する。候補ごとに単語と意味の input があるため、1500 候補では初期表示の DOM に入力欄が多くなる。今回のブラウザ操作では動作したが、古い端末での表示負荷は未確認。

**実装案**

仮想化ではなく、最初は 200 件を表示し、「さらに表示」で 200 件ずつ追加する最小の段階表示にする。検索と一括操作は、表示中の候補だけでなく候補全件を対象にする。

**受入条件**

- 1500 候補の初期表示で、DOM 内の input 数が 400 以下。
- 保存結果の件数は従来と同じ。
- 既存テストがすべて緑。
- 版を進める。
- 学習履歴・同期・教材品質の高リスク領域には触れない。

### 起票する issue の本文案（3 件）

#### A. 引き継ぎコードを再発行して旧コードを無効にする

**背景**

引き継ぎコードは同期データへの全権限を持つが、現在は失効・再発行の UI がない。紛失や漏えいが疑われる場合に古いコードを止められず、2026-07-10 の再確認レビューでも P1 として指摘されている。

**実装案**

設定に「新しいコードを発行して古いコードを無効にする」操作を追加する。再発行後、既存端末を新しいコードで再接続する手順を画面で案内する。

**受入条件**

- 再発行前のコードによる GET/PUT は 403 になる。
- 既存端末が新しいコードで再接続できる案内を表示する。
- 再発行で学習データを一切変更しない。
- 同期・秘密情報を扱う高リスク変更として Mode D で進め、作成者とレビュアーを分ける。

#### B. 設定と初回導線の説明を短くする

**背景**

設定画面に引き継ぎコードや旧キーの注意が重なり、初回取り込みでは「サンプルを入れてクイズ」へ進むより鍵の注意が前面に出ている。必要な注意を保ちながら、中高生が最初の学習に進みやすい表示にする。

**実装案**

設定タブの先頭を、引き継ぎコードの状態（控え済み／未控え）と 1 ボタンにまとめる。旧キーの注意は「詳しく」に畳む。初回の取り込み画面では、鍵の注意より「サンプルを入れてクイズ」を前面に出す。

**受入条件**

- 1.0.139 の警告帯（コード未控えの間は上部に出る）を残す。
- `npm test` の `a11y-audit` が緑。
- 文言は中高生が読める長さにする。

#### C. サンプル単語帳ごとに選定方針を説明する

**背景**

「単語を取り込む」画面には、サンプルが独自選定で特定の教材や市販単語帳の転載ではないという注記がある。一方、各サンプルのレベルの目安や収録方針は画面から分からない。

**実装案**

各サンプルの説明に、選定の考え方（レベルの目安、語数、どんな語を入れて何を入れていないか）を 1〜2 文で加える。出典コーパスの明示はライセンス確認後に別途判断し、この issue では扱わない。

**受入条件**

- 変更は説明文のみとする。
- 教材データを変更しない。
