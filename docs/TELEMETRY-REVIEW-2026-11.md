# テレメトリの読み方と判断の枷（ロードマップ 2026-07 の C）

作成: 2026-11-05 / 状態: **手順と判断基準のみ。数値は未取得**（この文書を書いた環境に Cloudflare の読み取り権限が無いため）。

ロードマップ C は「2〜4 週間ためてから読む」とし、計測の起点は 2026-07-26。本日で 14 週分たまっているはずなので、
読む時期は来ている。ここでは **何を取り、何が出たらどう決めるか** を先に固定し、数字は取れた人が §3 へ埋める。
先に基準を書いておくのは、数字を見てから基準を動かさないため。

## 1. 取り方

```sh
# Cloudflare の権限がある端末で（wrangler login 済み、または CLOUDFLARE_API_TOKEN / CLOUDFLARE_ACCOUNT_ID）
node tools/telemetry-report.mjs --out ./telemetry-out
# SQL だけ見る / 手で貼る
node tools/telemetry-report.mjs --print-sql
```

- 読むのは `telemetry` テーブルだけ。`rate_limits`（IP を含む）には触れない（`docs/telemetry.md`「匿名性の設計」）。
- 出力は Markdown と JSON。**数値を含むレポートはリポジトリに入れない**（docs には判断だけを残す）。
- 保持期限は 180 日なので、2026-07-26 以降の全期間がまだ残っている。次に読むときは消え始めている。

## 2. 読む前に知っておくこと（数字を誤読しないため）

| 事実 | 影響 |
|---|---|
| 利用者は開発者本人＋既存ユーザー 1 名（ロードマップ「現在地」） | 件数は 1〜2 人分。比率で考え、絶対数で機能の優劣を言わない |
| 利用回数は端末内で集計し 1 日 1 回まとめて送る | `reports` は「送信のあった端末日」の近似。`total` が解答数 |
| オプトアウトが設定にある | 本人がオプトアウトしていれば本人分は無い |
| `account-*` は Phase C で定義したが本番フラグは OFF | **0 件が正常**。0 件以外ならフラグ OFF なのに記録された経路を疑う |
| `sync-v2-native-issue` 等は 2026-07-26 まで許可リスト漏れ | それ以前の 0 は「無かった」ではなく「取れていなかった」 |
| エラーの `name` はメッセージ 120 文字、秘密は伏せ字 | 同じ原因が文言違いで分かれる。`detail` の stack で束ねる |

## 4. 判断の枷（数字を見る前に決めた基準）

| 問い | 基準 | 出たときの行動 |
|---|---|---|
| 使われていない機能は何か | 全期間で 0 件、かつ直近 30 日も 0 件の `USAGE_NAMES` | **UI から畳む候補**として起票。削除はしない（利用者 2 名のうち片方が使わないだけの可能性） |
| 頻出エラーは何か | 直近 30 日で 3 件以上、または最新版（1.0.141 以降）で再現しているもの | 次の修正対象。版が古いだけなら対象外 |
| AI 抽出はどれだけ使われるか | `ai-extract` と `ocr-run` の合計 ÷ 送信のあった日数 | 課金（ロードマップ E）の原価見積の根拠。1 日 1 回未満なら E は引き続き保留 |
| 復元導線は機能しているか | `recovery-prompt-shown` に対する `-restore` の比率 | `-new` が多ければ「空で起動した人が復元を選ばない」= 文言の見直し。shown 0 なら保存消失は起きていない |
| Phase D（パスキー導線）を進めるか | 本番フラグ ON 後に `account-register` が付き始めてから | フラグ OFF の今は判断できない。D は C の数字に依らず、Phase C の受入（実機）が先 |
| E（課金）・F（通知・FSRS） | 利用者数が 2 名のままなら着手しない（ロードマップの原則「使われ方が分かる前に大きな投資をしない」） | 据え置き。再評価は次回（180 日の保持が切れる前、2027-01 まで） |

## 5. 取れていない間にできること

- `tools/telemetry-report.mjs` は手元の SQLite（migrations 適用済み）に `--sqlite` で流せる。SQL の正しさはそれで確認済み。
- 本番の数字は Cloudflare の権限がある端末で §1 を実行する。クラウドの作業環境から読むなら、環境の秘密情報に
  D1 読み取りだけの API トークンを `CLOUDFLARE_API_TOKEN`、アカウント ID を `CLOUDFLARE_ACCOUNT_ID` として置く。
