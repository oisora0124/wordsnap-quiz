## 1. 取り方

```sh
# Cloudflare の権限がある端末で（wrangler login 済み、または CLOUDFLARE_API_TOKEN / CLOUDFLARE_ACCOUNT_ID）
node tools/telemetry-report.mjs --out ./telemetry-out
# SQL だけ見る / 手で貼る
node tools/telemetry-report.mjs --print-sql
```

- 読むのは `telemetry` テーブルだけ。`rate_limits`（IP を含む）には触れない（`docs/telemetry.md`「匿名性の設計」）。
- 出力は Markdown と JSON。**数値を含むレポートはリポジトリに入れない**（docs には判断だけを残す）。
- 保持期限は 180 日なので、2026-07-26 以降の全期間がまだ残っている。次に読むときは消え始めている。

## 4. 判断の枷（数字を見る前に決めた基準）

| 問い | 基準 | 出たときの行動 |
|---|---|---|
| 使われていない機能は何か | 全期間で 0 件、かつ直近 30 日も 0 件の `USAGE_NAMES` | **UI から畳む候補**として起票。削除はしない（利用者 2 名のうち片方が使わないだけの可能性） |
| 頻出エラーは何か | 直近 30 日で 3 件以上、または最新版（1.0.141 以降）で再現しているもの | 次の修正対象。版が古いだけなら対象外 |

## 6. 取れていない間にできること

- `tools/telemetry-report.mjs` は手元の SQLite（migrations 適用済み）に `--sqlite` で流せる。SQL の正しさはそれで確認済み。
- 本番の数字は Cloudflare の権限がある端末で §1 を実行する。クラウドの作業環境から読むなら、環境の秘密情報に
  D1 読み取りだけの API トークンを `CLOUDFLARE_API_TOKEN`、アカウント ID を `CLOUDFLARE_ACCOUNT_ID` として置く。
