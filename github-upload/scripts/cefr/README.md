# 内蔵CEFR表の作り方

`publish/index.html` の `BUILTIN_LEVEL_GROUPS`（Cefrモジュール内）を作り直す手順。
サンプル単語集を増やしたり入れ替えたりしたら、ここを流し直す。

```bash
node scripts/cefr/build-cefr.mjs   # Datamuseの md=f を取得 → cefr-builtin.json
node scripts/cefr/apply-cefr.mjs   # index.html へ差しこむ
npm run sync:html && npm test
```

同じ入力なら何度流しても同じ結果になる（冪等）。

## なぜ焼きこむのか

CEFRは実行時に Datamuse の `md=f`（使用頻度）を1語ずつ引き、`levelFromFrequency()` で
レベルへ落としている。1集300語のうちは実害がなかったが、**1集1500語になった時点で
実質破綻していた**。

実測（1500語を取り込んだ直後）:

| | CEFRが付いた語 |
| --- | --- |
| 焼きこむ前 | 72語 / 1500（4.8%） |
| 焼きこんだ後 | **1500語 / 1500（100%）** |

内訳は手書きの `OVERRIDES` 33語＋候補一覧で解決した60語だけで、残りは
「保存した単語」画面を何度もめくらない限り未判定のまま残っていた。
その状態ではクイズのCEFRフィルタ（A1〜C2／未判定）がほぼ機能しない。

ビルド時に一度引いておけば、利用者の端末は**通信ゼロ**でレベルを表示できる。
オフラインでも効く。判定の中身は実行時に引いた場合と同じなので、`estimated` は
`true` のままにしてある（人が確かめた `OVERRIDES` だけが `false`）。

## しきい値

`build-cefr.mjs` はアプリの `levelFromFrequency()` と同じ計算をする。
ずれると表示が食い違うので、**HTMLから実際のしきい値を読み出して一致を確認**し、
違っていればビルドを止める。

| 頻度 f | レベル |
| --- | --- |
| ≥100 | A1 |
| ≥30 | A2 |
| ≥8 | B1 |
| ≥2 | B2 |
| ≥0.5 | C1 |
| それ未満 | C2 |

## 外部から取り込んだ単語について

内蔵表はサンプル単語しか収録しない。貼り付けやOCRで入れた単語は、従来どおり
「保存した単語」画面を開いている間に少しずつ埋まる。

1.0.65 で、その対象を**表示中の100行から単語帳の全語へ広げた**（`savedWordsInScope`）。
送信のきっかけは今までどおりライブラリ画面を開いたときだけで、画面を離れれば止まる。
送る内容も英単語だけで変えていない。外したのは「ページングで表示した行だけ」という
制約で、これがあると1500語の単語帳では「さらに表示」を14回押して回らないと埋まらなかった。
