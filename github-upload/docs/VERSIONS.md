# バージョン履歴

アプリのフッターに出る「バージョン」の履歴。

## 採番の決まり

- 形式は `x.y.z`。**配信物（`publish/` または `functions/`）を変えるコミットごとに `z` を1つ進める。**
  設計書・レビュー記録・テストだけの変更では進めない（利用者に届く変更がないため）。
- バージョンは3か所に同じ値で入る。ズレは `scripts/check-release.mjs` が落とす。
  1. `package.json` の `version`
  2. `publish/index.html` のフッター表示（`app-footer-version`）
  3. `publish/index.html` の `APP_REV`（テレメトリの `app_rev` として送られる）
- 進め忘れは CI（`scripts/check-version-bump.mjs`）が落とす。
- `y` を上げるのは、利用者の操作手順が変わるような大きな機能追加のとき。`x` は現状据え置き。

利用者が「バージョン 1.0.71 で起きた」と伝えてきたら、そのまま
`SELECT * FROM telemetry WHERE app_rev = '1.0.71'` で絞り込める。

## 1.0.0 について

`1.0.0` はフッターにバージョン表示を入れた時点（`0178b5b`, 2026-07-22）の状態を指す。
その後 2026-08-01 までの間、表示は `1.0.0` のまま **配信物への変更が59回** 積み上がっていた。
下の表の `1.0.1` 〜 `1.0.59` はその59回を後から採番したもので、当時そのバージョンが
アプリに表示されていたわけではない（記録として残すために遡って割り当てた）。
実際にフッターへ数字が出るのは、この採番の仕組みを入れた `1.0.60` からで、以後は変更のたびに進む。
