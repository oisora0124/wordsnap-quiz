# つづり練習モード（タイピング入力）設計案

作成: 2026-08-12 / 状態: **設計のみ・未実装**

## この文書の位置づけ

引き継ぎ書の「未対応の改善候補」で唯一残っていたのがタイピング入力モード。
実装するかを検討した結果、**フル機能のタイピングモードは作らない**と判断した。
代わりに、学習データに一切触れない「おまけ」に閉じ込めた形なら作れる、という
結論に至った。その設計を残しておく。着手は未定。

## なぜフル実装しないか

### 使われない見込み

iPhone での利用が主。英単語の自由入力は日本語キーボードからの切り替えが要り、
1問あたりの所要時間が4択の数倍になる。9,700語規模では、その差が
「今日はやらない」に直結する。

### 学習効果は否定できない（ここは作らない理由にならない）

選択肢から選ぶより自分で産出するほうが定着に効くのは比較的一貫した結果で、
4択は「見れば分かる」で通ってしまう。**効果がないことを理由にはできない。**

### 決定的な理由：採点の曖昧さが学習データを壊す

自由入力の採点には必ず判定困難が出る。

- つづり揺れ（`colour` / `color`）、活用形、冠詞
- 1語に複数の訳がある語
- 単なるタイプミス

誤って「不正解」と判定すると **SRS の状態が実際に下がる**。これは
`CLAUDE.md` が高リスクと定める「学習履歴・復習アルゴリズム」に正面から当たる。
1.0.75〜1.0.77 の学習状態マージを全面撤回したのと、リスクの質が同じ。

### 既存機能で産出練習はほぼ取れている

フラッシュカードの自己申告（覚えている / あやふや / もう一度）は、頭の中で
産出してから自己採点する仕組みそのもの。逆方向出題（1.0.79/1.0.81）も入った。
タイピングが追加で得るのは実質「つづりを正確に書けるか」だけ。

## 設計の核：`gradeQuiz` を呼ばない

`gradeQuiz`（`publish/index.html`）は SRS 更新以外に9つの副作用を持つ。

`word.stats` / `word.history` / `updateStreakOnAnswer()` / `bumpTodayAnswerCount()` /
`blockedUntil` / `recordRecoveryProbeAnswer()` / `verifyConfidenceOnAnswer()` /
`recordReviewEvent()` / `appState.quizCounter`

「SRS に反映しない」をフラグで実現すると、この9箇所すべてに分岐が入る。
既存の全出題経路に影響する変更になり、撤回した学習状態マージと同じ形になる。

**そこで `gradeQuiz` を一切呼ばない別経路にする。既存の採点・SRS コードは1行も変えない。**
これがこの案を安全かつ安く成立させる唯一の条件で、ここを崩すなら作らないほうがよい。

## 構成

| 要素 | 方針 |
|---|---|
| 対象語 | `difficultQuizWords()` を再利用。誤答1回以上かつ正答率80%未満 |
| 語数 | `orderIdsByPriority()` で並べて先頭10語まで |
| セッション | `typingSession` を新設。`flashcardSession` と同じ「別モードは別セッション変数」の型 |
| 永続化 | **なし**。`appState` に書かない。結果は終了画面で見せて捨てる |
| 導線 | 「苦手だけ解く」の隣に「つづり練習（記録に残しません）」。名前で明示しないと「やったのに記録されない」と混乱する |

### iPhone での入力（実装の要）

属性を付けないと iOS が先頭を自動で大文字化し、自動修正も入って入力が成立しない。

```html
<input type="text" lang="en" inputmode="text"
       autocapitalize="off" autocorrect="off" autocomplete="off" spellcheck="false">
```

既存の `type="text"` 4箇所と同じ書き方にそろえる。

### 判定

`normalizeTypingAnswer()` を新設：トリム → 小文字化 → 連続空白の圧縮 → 末尾ピリオド除去。

| 結果 | 条件 |
|---|---|
| 正解 | 正規化後に完全一致 |
| おしい | レーベンシュタイン距離1以内（`colour`/`color`、タイプミス） |
| 不正解 | それ以外 |

3値にするのは `colour` を「不正解」と言い切らないため。既存の `spellingDistance()`
が使えるか確認してから、必要なら流用する。

**どの判定でも `appState.words` には書かない。** 誤判定してもデータは壊れない。

### 明示的に触らないもの

連続記録🔥 / デイリーゴール / `stats` / `history` / `blockedUntil` /
`masteryVerify` / `recordReviewEvent` / `quizCounter`

## 検査

最重要は次の1本。

> **つづり練習を1セッション通しても `appState` が一切変わらないこと**（前後を deep-equal で固定）

これが通っている限り、判定ロジックが多少雑でも学習データは安全。
加えて正規化と距離計算の純粋関数テスト。
`scripts/context-quiz.test.mjs` / `scripts/reverse-quiz.test.mjs` と同じ
node:vm 抽出方式が使える。

## 規模

実装 200〜300行 ＋ テスト10本程度。既存コードの変更は導線ボタンの追加だけ。

## 実装するときの判断基準

次のいずれかを崩すことになったら、作らずに閉じる。

- `gradeQuiz` / `applyLearningResult` に手を入れる必要が出た
- 練習結果を `appState` に保存したくなった（同期・移行の対象になる）
- 「おしい」を正解として SRS に通したくなった
