# ハッシュ型CSP の仕組みと、その落とし穴（2026-08-07）

WordBank は `script-src` に `'unsafe-inline'` を使わず、
**インライン `<script>` ごとの SHA-256 を `_headers` に列挙**している。
XSS で注入された `<script>` はハッシュが一致しないので、ブラウザが実行を拒む。

| ファイル | 役割 |
| --- | --- |
| `scripts/csp-hashes.mjs` | HTML から script 要素を走査してハッシュを計算する |
| `scripts/sync-html.mjs` | `_headers` の `script-src` を書き換え、ルート `index.html` へコピーする |
| `scripts/check-release.mjs` | 全ハッシュが `script-src` に載っているか照合する |
| `scripts/csp-hashes.test.mjs` | 上記の不変条件を固定する（`npm test`） |

## この仕組みの怖いところ

**壊れても、壊れたことがローカルでは分からない。**

ハッシュが欠けたインライン `<script>` は、ブラウザが実行を拒否する。
しかし `_headers` は Cloudflare Pages が配信するときにしか効かないので、
手元でファイルを開いても、`npm test` を回しても、何も起きない。
**気づくのは公開した後、利用者の画面が動かなくなってから**になる。

さらに悪いことに、**生成側と照合側が同じ `inlineScriptHashes` を使っている**。
この関数が script 要素を取りこぼすと、両方の目が同時に塞がる。
「ハッシュは全部揃っている」と judged したまま本番だけ壊れる。

## 実際にあった穴（2026-08-07 に修正）

### 1. 属性の付いた `<script>` を丸ごと取りこぼしていた

以前の走査は `/<script>([\s\S]*?)<\/script>/g`。つまり**属性のない裸の
`<script>` しか拾わない**。

```html
<script type="module">…</script>   ← ハッシュが計算されない
<script defer>…</script>           ← 同上
<SCRIPT>…</SCRIPT>                 ← 同上
```

現在の `index.html` は3つとも裸の `<script>` なので**実害は出ていなかった**。
だが、この先だれかが `type="module"` を1つ書いた瞬間に、
ローカルのゲートは全部緑のまま本番だけが壊れる。

いまは属性付き・大文字・外部 `src` 付きを明示的に扱い、
閉じタグの無い `<script>` は例外にしている。

### 2. `script-src` が最後のディレクティブだと、置換が黙って失敗していた

正規表現が末尾の `;` を必須にしていた。ディレクティブを並び替えて
`script-src` を最後に置いた瞬間、置換が起きなくなる。

### 3. 「先頭ハッシュが据え置き」だと、2つ目以降が古いまま成功扱いになった

失敗条件が `置換で変化なし かつ 先頭ハッシュが本文に無い` だった。
先頭の `<script>` を変えずに2つ目だけ変えた場合、
置換に失敗しても先頭ハッシュは本文にあるので、**成功として通ってしまう**。
その `<script>` だけが本番でブロックされる。

いまは「置換対象が存在するか」を先に判定し、更新後に**全ハッシュを1件ずつ**確認する。

### 4. 属性値の中の `>` でタグが終わったことにしていた

開始タグの終わりを `[^>]*>` で探していた。**引用符の中の `>` はタグを終わらせない**
というHTMLの規則を無視している。

```html
<script data-x="a>b">alert(1)</script>
```

これを走査すると本文が `b">alert(1)` になり、実際に実行される `alert(1)` とは
別のハッシュが `_headers` に載る。つまり**そのscriptだけ本番でブロックされる**。
いまは引用符を追いながら `>` を探している。

### 5. HTMLコメントの中の `<script>` を実在する要素として数えていた

ブラウザはコメント内を実行しない。数えると実在しないscriptのハッシュが載り、
要素数の突き合わせもずれる。いまはコメントを読み飛ばす。

### 6. HTMLを先にコピーしていたため、失敗時に中途半端な状態が残った

`copyFileSync` が `_headers` の更新より前にあった。CSPの計算や検証で
例外が出ると、**ルート `index.html` だけ新しく、`_headers` は古い**状態になる。
気づかずコミットすると、新しい `<script>` は古いハッシュとしか照合されず本番で落ちる。

いまは `_headers` を確定させてからコピーする。

### 7. 属性値の中の `src=` を外部scriptと誤認していた

`src` の有無を正規表現 `/(^|\s)src\s*=/` で判定していた。

```html
<script data-note="x src=/a.js">alert(1)</script>
```

これを外部scriptと判定すると、**実際に実行される本文のハッシュが落ちる**。
いまは属性を引用符ごと解析して属性名だけを取り出している。

### 8. `<!--` をHTMLの状態と無関係に探していた

属性値や `<style>` / `<textarea>` の中に `<!--` があると、そこから `-->` まで
飛ばして**後続の本物の script を取りこぼす**。
いまはタグの外・raw text の外にある `<!--` だけをコメントとして扱う。

### 9. EOF で閉じないタグを成立したものとして扱っていた

`<script>A</script` （`>` が無いままEOF）を閉じタグとみなしていた。
HTMLの仕様ではEOFの未完了タグはタグとして成立しない。いまは例外にする。

### 10. 改行を正規化していなかった

ブラウザは入力の CRLF と単独 CR を LF へ正規化してから解析し、
**CSPのハッシュはその正規化後の本文**に対して計算される。
ファイルがCRLFになった瞬間に全ハッシュが食い違う。いまは揃えてから計算する。

### 11. `_headers` 全体の最初のCSP行を対象にしていた

将来 `/api/*` 用のCSPを先に足すと、そちらだけ更新され、
ページ用 `/*` のハッシュが古いまま残る。いまは `/*` ブロックに限定している。

## 走査の約束ごと（ブラウザのHTMLパースに合わせてある）

- 開始タグの `>` は**引用符の外側**でだけ探す。
- タグ名は `<script` の直後が空白 / `/` / `>` のときだけ script とみなす
  （`<scriptx>` は別のタグ）。
- 本文は**最初の `</script`**（直後が空白 / `/` / `>`）で終わる。
  `</scriptx>` は本文の終わりではない。
- 走査は閉じタグの先から再開する。本文の途中から再開すると、
  JSの文字列やコメントに書かれた `"<script>"` を要素と誤認する。
  実際に `index.html` のコメント内に `<script>` と書かれた箇所が存在する
  （OCRの自前配信についての説明）。ここを誤認すると、ハッシュが1つずれて本番が壊れる。
- HTMLコメント `<!-- ... -->` の中は要素として数えない。
  ただし `<script>` の**本文の中**にある `<!--` はJSのコードなので触らない
  （走査が本文を丸ごと飛ばすので、自然にそうなる）。
- `src` 付きは本文を持たないのでハッシュ対象にしない。
  これらは `'self'` で許可される。
- 閉じタグの無い `<script>` は例外にする。黙って続けると、
  残り全部を本文としたハッシュが載って本番が壊れる。

## 検査

`npm test` に同梱。26件。走査（属性付き・大文字・外部src・属性値の中の `>`・
属性値の中の `src=`・HTMLコメント・タグや raw text の中の `<!--`・
`<style>` / `<textarea>` の中身・DOCTYPE・閉じタグの変種・`<scriptx>`・
本文中の `</scriptx>`・本文中の文字列 `"<script>"`・閉じタグ無し・CRLF）と、
`_headers` の書き換え（全ハッシュ反映・末尾ディレクティブ・`/*` ブロック限定・
コメント行を壊さない・先頭据え置きでも2つ目が更新される）を固定している。
最後に、実ファイルどうしの突き合わせ（HTMLのハッシュ集合 ＝ `script-src` の
ハッシュ集合、要素数 ＝ 閉じタグ数）も見る。

変異テストで13通りの壊し方を試し、すべて検出することを確認済み。

**ここでも、自分の変異テストだけでは足りなかった。**
上の 7〜11（属性値の `src=`、タグ内の `<!--`、EOFのタグ、CRLF、`/*` ブロック限定）は、
自分の変異テストが全部OKになった後に **Codex の独立レビューが見つけた**もの。
さらに、その修正後の変異テストでも2件がすり抜け、
どちらもテストケースの作り方が甘いせいだった:

| すり抜けた変異 | 原因 |
| --- | --- |
| HTMLコメントを飛ばさない | コメント本文に `>` が無く、`<!` の読み飛ばしと同じ結果になっていた |
| CSP行以外の script-src も置換する | `script-src` を含むコメントを `/*` ブロックの**外**にしか置いていなかった |

なお `check-release.mjs` にも同じ突き合わせを足しかけたが、
`npm test` が両方を走らせるため完全な重複になり、変異テストでも
独立に落ちないことが分かったので撤回した。検査は1か所に寄せてある。
