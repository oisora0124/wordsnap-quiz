# アクセシビリティの検査方針（2026-08-07 / 1.0.72）

利用者が増えると、支援技術（スクリーンリーダー、キーボードのみの操作、画面拡大）で
使う人の割合も必ず増える。この種の欠陥は**見た目にも成績にも出ない**ので、
気づくのは「使えなかった人」が黙って離れた後になる。
そこで、機械判定できる範囲は恒久的なゲートにして、退行を止める。

## 何を自動で見ているか

`npm test` が2つ走らせる。どちらも npm 依存を増やしていない
（jsdom / axe-core は node_modules を持ち込むので使わない）。

| 検査 | 実体 | 対象 |
| --- | --- | --- |
| 静的検査 | `scripts/a11y-audit.mjs` | `publish/index.html` の構造。違反があれば exit 1 |
| 実行テスト | `scripts/a11y-dialog.test.mjs` | モーダルのフォーカス挙動。実コードを `node:vm` で動かす |

単体で動かすときは `npm run test:a11y`。

### 静的検査の12ルール

| ルール | 何が壊れるか |
| --- | --- |
| `duplicate-id` | `getElementById` が先勝ちになり、aria参照も壊れる |
| `broken-aria-reference` | `aria-labelledby` 等の参照先が無く、名前が付かない |
| `broken-label-for` | `<label for>` の参照先が無く、ラベルが結び付かない |
| `invalid-role` | 不正な role は無視され、暗黙の role も失われる |
| `positive-tabindex` | DOM順と食い違うフォーカス順ができる |
| `img-missing-alt` | 画像の内容が読み上げられない |
| `button-no-name` / `button-symbol-only` | ボタンが無音、または「✕」だけで意味が伝わらない |
| `link-no-name` / `link-symbol-only` | 同上（リンク） |
| `control-no-label` | 入力欄が何の欄か分からない |
| `focusable-in-aria-hidden` | フォーカスは行くのに読み上げには存在しない |
| `heading-skip` | 見出しの目次が崩れ、飛ばし読みができなくなる |

対応するのは WCAG 2.1 の 1.1.1（非テキスト）、1.3.1（情報と関係性）、
2.4.6（見出しとラベル）、4.1.2（名前・役割・値）の、構造だけで判定できる部分。

検査そのものが空振りしないよう、12ルール全部について「わざと違反を作ると検出する」
「正しい記述では検出しない」を変異テストで確認した。境界条件のバグ
（開始タグ直後の子を範囲外と判定していた）はこの過程で見つけて直している。

## 自動で見ていないもの（＝人が見るしかない）

静的解析では原理的に判定できない。誤って「検査済み」と思わないための一覧。

- **色のコントラスト比** — CSS変数とテーマ切替の組み合わせで実測が要る
- **`aria-live` が実際に読み上げられるか** — 属性の有無しか見ていない
- **キーボードだけで全機能を完遂できるか** — 通しの手動操作が要る
- **200%拡大時の再配置**
- **正誤や状態を色だけで伝えていないか**
- **タッチ領域の大きさ**

これらを見るときは、NVDA＋Chrome / VoiceOver＋Safari / TalkBack＋Chrome の
いずれかで、「単語を追加 → 保存 → 10問解く → 復習を確認」を通しで試す。

## モーダルのフォーカス閉じ込め（1.0.72で入れた）

`aria-modal="true"` は**読み上げ上だけ**背景を隠す。Tabキーの移動は止めない。
トラップが無いと、Tabで背景の要素へフォーカスが抜けたとき、
**フォーカスはそこにあるのに読み上げは無音**という最悪の状態になる。

1.0.71 時点では、チュートリアルには手書きのトラップがあり、
V2お知らせダイアログには**無かった**。手書き版は対象ボタンを直接列挙していたため、
ボタンを足すと順路から漏れる作りでもあった。

`trapDialogTab(dialog, event)` に共通化し、対象は都度DOMから引くようにした。
両ダイアログに配線してある。`scripts/a11y-dialog.test.mjs` が、
配線が外れること・`preventDefault` が抜けること・`hidden` の除外が消えること・
開閉時のフォーカス保存と復帰が消えることを、それぞれ落ちる形で押さえている。

## 見出し階層（1.0.72で直した）

設定は `h2`。その中の同期V2ブロックが `h4` で、`h3` を飛ばしていた。
`h3` に直し、`.sync-v2-panel h3 { font-size: 1em }` で見た目は `h4` のときのまま保った。

## 分かっている限界

- 静的検査は `publish/index.html` の**静的なHTMLだけ**を見る。
  JSがテンプレート文字列から組み立てる部分（`enrich-title` など）は対象外。
  ここを増やすときは、生成後のHTMLを検査に流す仕掛けが要る。
- `a11y-audit.mjs` のHTML走査は自前のタグスキャナで、厳密なHTMLパーサではない。
  極端に壊れたマークアップでは判定を誤りうる。現状の書き方では問題ない。
